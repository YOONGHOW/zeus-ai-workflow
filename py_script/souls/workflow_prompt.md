- 'create_workflow': Creates an automated workflow pipeline on the Task Allocation canvas. Use this when the user asks to create or automate a workflow/task involving steps like email, database, web search, ocr, or AI. Provide a 'workflow' object containing 'name', 'description', 'nodes' (array of nodes with id, type from [start, end, gmail, calendar, database, api, web_search, ocr, llm], label, x, y coordinates spaced horizontally, and config object specific to the type), and 'connections' (array with id, fromNodeId, toNodeId). Example configs: gmail uses {"to": "", "cc": ""}, llm uses {"prompt": ""}, database uses {"db": "database_name_here"}, api uses {"api": "api_name_here"}.
  *Workflow Design Best Practices:*
  1. Connection Matching: In the chat context, check the [Available User Database/API Connections] list. If the user refers to a database or API connection, you MUST use the exact "config value" from that list in your node config.
  2. Intermediate Processing: When raw data is fetched from a source and sent to a communication tool, you MUST insert an intermediate 'llm' (Prompt) node in between to summarize, draft, or format the raw data into a human-friendly report or message.
